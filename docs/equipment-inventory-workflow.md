# Workflow оборудования без сканера

Страница: [`/stock`](https://GIN1104.github.io/led-warehouse/stock/) (нав «Оборудование»).

## Статусы qty-строки

| Статус | Смысл |
|--------|--------|
| `available` | Доступно на складе |
| `reserved` | Забронировано (заказ / импорт mapper) |
| `checked_out` | Вышло со склада (вручную; позже — рамка) |
| `needs_repair` | Нуждается в ремонте |
| `in_repair` | В ремонте |

Переходы пишутся в `equipment_status_history`.

## Flow для склада

1. **Сводка по SKU** вверху `/stock`: всего / на складе (`available`) / в работе (`reserved`+`checked_out`, со ссылкой на заказ) / в ремонте (`needs_repair`+`in_repair`).
2. **Добавить** позицию вручную → статус `available`.
3. **Импорт Excel/CSV** из mapper (кнопка на `/stock`) → строки `reserved`. Файл с ПК. Достаточно колонок **название + количество** (code не обязателен — присваивается стабильно). Опционально **категория/группа**. Папка Drive `LED Warehouse / Excel` на `ledvision2026.il@gmail.com` — скачать и загрузить; Drive Picker после scope `drive.file`. Подробности: [excel-sku-hierarchy.md](excel-sku-hierarchy.md).
4. **Группы и варианты** на `/stock`: создать группу («Телевизор»), добавить дочерние SKU (`TV 32"`, `40"`…), сортировка внутри группы.
5. **Вышло со склада** → `checked_out` (кнопка в строке).
6. **Нужен ремонт** / **В ремонте** — можно указать **часть qty** (например 2 из 80); остаток остаётся в текущем статусе. **Вернуть в доступно** — по допустимым переходам.
7. Сортировка и фильтр по статусу / поиску в шапке таблицы.

Импорт заказа на `/orders` по-прежнему создаёт бронь заказа и дополнительно зеркалит qty-строки оборудования как `reserved` (в т.ч. с авто-SKU по названию).
